# 插件导入

在「插件导入」上传当前平台的 ZIP、TAR.GZ 或 TGZ 成品包。单包最大 512 MiB；所有插件资料从包内读取，页面不补填名称、版本或启动参数。

## 安装包要求

根目录必须包含 `mengka-plugin.json`，使用 `schema: 3`，完整声明 `plugin_id`、`name`、`version`、`min_framework`、`author`、`notes` 及 `runtime.admin`。`runtime.entry` 必须指向包内安全的相对路径。

支持的接入方式：

| 方式 | 声明 | 连接 |
| --- | --- | --- |
| WebSocket | `runtime.transport: "websocket-v1"` | 当前正向或反向 WS 接口；托管运行时由框架注入连接配置 |
| 原生 IPC | `runtime.transport: "native-ipc-v1"`、`runtime.api_version: "1"` | 框架通过标准输入输出通信，无需额外端口 |

不再接受旧清单、隐式传输、旧 IPC 版本或自动猜测启动程序。安装、更新和每次启动都会复核清单与完整文件记录；缺少记录的旧安装须重新导入当前包。协议与打包细节见[当前原生插件规范](https://github.com/Carlor-Official/Mengka-NT/blob/main/docs/native-plugins.md)。

## 导入与更新

1. 点击「上传插件」并选择文件。
2. 核对包内资料及请求的能力，确认来源可信。
3. 有 Web 管理端时，先配置访问入口。
4. 点击「导入并安装」，查看后台进度与实际连接状态。

同一插件上传更高版本时在原卡片更新。新包通过校验后才切换程序，启动失败会恢复旧程序。新增能力时需核对权限差异；失败请求不会自动重放。旧程序自身不符合当前协议时，需上传符合规范的包。

## 生命周期与数据

支持启动、停止、日志、配置、数据目录和 Web 管理端。卸载程序可以保留业务数据；彻底删除须单独确认，自定义外部目录不会被清除。旧协议的运行兼容已移除，保留数据不代表允许继续运行旧包。
