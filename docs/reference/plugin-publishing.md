# 发布外部插件

框架不再提供官网审核市场和在线下载。开发者应在自己的发布仓库维护版本、安装包、校验值、更新日志和接入说明。用户取得成品包后，可以在「插件 → 插件导入」手动上传，也可以自行部署后通过 WebSocket 接入萌卡 NT。

## 推荐发布结构

每个正式版本至少提供：

- Windows AMD64 成品包；
- Linux AMD64 成品包；
- Linux ARM64 成品包；
- SHA-256 校验值；
- 当前版本更新日志；
- 正向和反向 WebSocket 配置示例；
- 数据目录、升级和回滚说明。

不要把源码仓库首页当成安装包。原生程序应按系统和架构分别构建，Node.js 或 Java 应明确运行时要求。

## 接入信息

文档应列出服务名称、默认端口、WebSocket 路径、令牌填写位置和可选管理端地址。不要在示例中放入真实令牌、密码、Cookie 或签名私钥。

用户可以把成品包上传到「插件导入」，由框架在本地完成安装和启动。自行部署的程序则在「插件对接」中创建正向或反向服务。框架不会从官网或第三方地址自动下载插件。

## v2.4.1 原生包示例

萌卡 NT 用户系统的已验证 Linux AMD64 原生包在[用户系统独立 Release](https://github.com/Carlor-Official/mengka-user-system-source/releases/tag/v2.0.17-native-ipc)发布。包版本为 `2.0.17`，最低框架版本为 `2.4.1`，传输为 `native-ipc-v1`。安装前下载同一 Release 的 `linux-amd64-native.json` 与 `SHA256SUMS.txt` 校验文件；安装时只从「插件 → 插件导入」上传，不要把包内程序拆出运行，也不要将原生插件端口暴露到公网。
