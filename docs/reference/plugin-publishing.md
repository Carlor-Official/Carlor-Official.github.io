# 提交与发布插件

萌卡 NT 官网的发布表单、审核系统和框架插件市场已经打通。开发者一次填写资料并提交审核；审核通过后，官网才会原子更新线上文章和市场目录。无需手写市场 JSON，也不需要再到投稿中心重复提交。

> 开发者平台与框架本地管理员是两个独立入口。本官网仅提供文档与资源导航，不提供普通用户注册、官网登录或框架初始化令牌。插件 ID 应保持稳定，它关联文章、安装记录、审核快照和运行配置。

## 发布流程

1. 使用管理员分配的开发者账号进入开发者平台，在插件管理中创建或更新插件。
2. 填写基础资料、平台安装包和接入信息。官网发布固定为「一体化部署 · 自动安装」，不再提供外部部署选项。
3. 核对接入模式、监听端口和 Web 后台信息；安装与配置说明、数据与目录说明为选填，无需填写 JSON。
4. 点击“提交审核”。系统会保存草稿、生成详情文章并建立审核快照。
5. 审批人员检查本次提交的完整详情、安装文件和接入信息。
6. 审核通过后，新快照才会发布并同步到框架插件市场。

这是一条完整流程，不再需要“先保存、进入 Halo 编辑器、返回列表后再次提交”。选择各系统安装文件后即可提交，不验证指纹、不要求包内声明，也不在发布时下载整包。

## 表单字段

| 项目 | 填写要求 |
| --- | --- |
| 插件名称 | 官网文章和插件市场显示名称 |
| 插件 ID | 稳定唯一标识，例如 `Bilibili-Utility-Suite` |
| 插件版本 | 当前发布版本，例如 `1.5.0` |
| 一句话介绍 | 插件市场卡片摘要 |
| 插件 Logo | PNG、JPG/JPEG 或 WebP，最大 5 MB；自动归一为 512×512 |
| 支持平台 | 仅 Windows、仅 Linux、Windows + Linux |
| 下载地址 | Windows x86_64、Linux x86_64、Linux ARM64 分别填写；识别后必须在候选附件中单选确认，三个目标允许选择同一个通用文件 |
| 更新日志 | 本次发布的变更说明，支持 Markdown |
| 接入模式 | 正向、反向或正向 + 反向 WebSocket |
| 监听端口 | 快捷添加服务时预填；无固定端口填 `0` |
| 内置 Web 后台 | 只有插件确实提供管理页面时才选择“支持” |
| 安装与配置说明 | 选填，说明必要业务配置 |
| 数据与目录说明 | 选填，说明数据保存及额外目录需求 |

标准事件名为：`group_message`、`friend_message`、`group_event`、`friend_event`、`bot_offline`。

## 审核与插件对接

官网不再收集 API 或事件权限勾选项。接入模式、监听端口和 Web 后台信息继续保留，方便框架自动配置插件连接。

- 一体化部署自动生成实际端口、令牌及连接配置，仍使用框架现有 WS 认证和事件订阅协议。
- 框架的“插件对接”继续支持手动添加正向、反向 WS 服务。
- 旧版发布记录已下架并保留作者和内容；外部部署草稿须补齐一体化安装包，重新提交审核，不能直接恢复上架。

所有公开 action 标准名见 [API 总览](/api/)。

## 安装包与启动入口

- Windows、Linux x86_64 和 Linux ARM64 应提供与目标平台匹配的可部署成品包。
- 普通 ZIP 或 TAR.GZ 成品包即可；不要求 SHA-256、签名文件或 `mengka-managed.json`。
- 框架安装时自动识别 Windows 可执行程序、Linux 可执行程序或启动脚本。多个候选程序时优先匹配插件名称及 start/run/main/app；无法唯一识别时提示整理安装包，不任意启动其他程序。
- 如果包内已有 `mengka-managed.json`，框架可以读取其启动参数和管理接口信息，不核对包内 ID、版本或指纹。
- 自动生成的连接文件与环境变量供插件读取；尚未支持读取这些信息的插件，可在启动后的管理端完成 WS 配置。

## 发布更新与版本连续性

在“管理我的插件”中选择“发布更新”。表单会载入已有资料和候选安装文件，核对版本及更新日志后重新提交。

| 状态 | 官网行为 | 框架市场行为 |
| --- | --- | --- |
| 草稿 | 仅作者可编辑 | 不显示 |
| 待审核（首次发布） | 审核人员可查看快照 | 不显示 |
| 待审核（已上架插件更新） | 新资料隔离在待审快照 | 继续显示上一审核版本 |
| 审核通过 | 同时提升待审字段、文章快照并发布 | 切换到新版本 |
| 审核驳回 | 保留线上版本，作者按原因修改 | 继续显示上一版本 |
| 已下架 | 停止公开发布 | 停止展示 |

提交审核后不能继续修改同一待审版本；这是为了保证审批人员看到的内容与最终发布内容完全一致。被驳回后可修正并再次提交。

## 下载与更新日志

- 单平台插件可填写直接压缩包或 Releases 页面。
- 更新日志在表单中单独填写并随本次安装包一起审核。
- 官网会为 Windows x86_64、Linux x86_64、Linux ARM64 分别识别候选附件并默认选择最匹配的文件。开发者必须在每组单选框中确认，也可以改选其他候选附件。
- 三组选择互不排斥；Shell、Java、Node.js 等真正跨平台或跨架构的成品包可以由 Windows 和两个 Linux 架构选择同一个文件。原生二进制仍应按平台和架构分别打包。
- 更新须重新提交审核，不会自动替换已审核版本。
- 一体化安装包支持 ZIP 或 TAR.GZ；不要把源码仓库首页当成安装包。

## 审核前自检

- 插件 ID 与历史版本及 `MENGKA_PLUGIN_ID` 一致；
- 至少一个平台下载地址有效，安装包可解压启动；
- Windows、Linux x86_64、Linux ARM64 安装包的目标架构正确，且每个包只有一个明确的启动入口；
- 接入模式和监听端口与实际运行方式一致；
- 配置密钥没有写入安装包、文章或普通配置默认值；
- 只有实际提供 Web 管理端时才启用“内置 Web 后台”；
- 更新日志、功能、安装方法和反馈渠道完整。

## 与其他业务的边界

- 开发者账号由管理员统一创建和管理，发布、管理和审批分别校验权限；不依赖本官网的普通用户注册。
- 审核人员授权不等于普通管理员权限；无审批权账号不能读取或处理待审插件。
- 开发者只能发布、编辑和提交自己的插件，不能管理其他作者的插件或直接审批上架。
- 插件文章只进入 `mknt-plugin-market` 分类，不占用普通投稿流程。
- 删除、下架和重新上架仍走独立受控流程，发布表单不会直接删除线上数据。
